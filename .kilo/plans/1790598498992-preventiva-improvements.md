# Preventiva App - Improvement Suggestions

## Current State Summary
- ✅ Supabase backend (PostgreSQL) with 131 boards + checklist definitions
- ✅ Internal username/password auth (no email, simple)
- ✅ Inspections with 3-state checklists (Conforme/Não conforme/N/A)
- ✅ Non-conformities workflow (Aberta → Em tratamento → Resolvida)
- ✅ Resolver tracking (who resolved each item)
- ✅ 6-month (semester) frequency with status calculation
- ✅ History view with board/person filters
- ✅ User management (create/delete with roles)
- ✅ Recent activity dashboard
- ✅ Deployed on Vercel + Supabase

---

## High-Impact Improvements

### 1. **Scheduled Notifications & Alerts** ⭐
**Problem**: Users forget when preventivas are due.
**Solution**:
- Add `next_due_date` column to boards (auto-calculated from last_inspection + frequency)
- Supabase Edge Function (cron) runs daily → checks due/overdue boards
- In-app notification bell (already has UI placeholder) + optional email
- Supervisor dashboard: "Vencendo esta semana" / "Atrasadas"

**Effort**: Medium | **Value**: High

---

### 2. **PDF/Excel Export Reports** ⭐
**Problem**: Need formal reports for management/audits.
**Solution**:
- "Exportar" button in Histórico view → generates PDF with:
  - Cover page (period, generated by, date)
  - Summary table (board, date, performer, status, NC count)
  - Detail pages per inspection (checklist + photos + NCs)
- Excel export for raw data analysis
- Use `jspdf` + `jspdf-autotable` or `exceljs`

**Effort**: Medium | **Value**: High

---

### 3. **Calendar View** 
**Problem**: Hard to visualize workload across months.
**Solution**:
- New "Calendário" nav item
- Monthly grid showing due dates (color: green=done, yellow=due soon, red=overdue)
- Click day → list inspections due
- Drag-drop to reschedule (updates board frequency logic)

**Effort**: Medium | **Value**: Medium-High

---

### 4. **Photo Management Improvements**
**Problem**: Photos stored as base64 in DB → large rows, slow queries.
**Solution**:
- Upload to Supabase Storage (bucket: `inspection-photos`)
- Store only path in `inspection_items.photo` and `non_conformities.photo`
- Add image compression (canvas resize) before upload
- Gallery modal in history view

**Effort**: Medium | **Value**: Medium

---

### 5. **Advanced Analytics Dashboard**
**Problem**: Only basic metrics cards exist.
**Solution**:
- Trend charts: NCs over time, by type, by location, by priority
- "Top 10 problematic boards" ranking
- MTTR (Mean Time To Resolve) for non-conformities
- Compliance rate % per board/type/location
- Use `recharts` or `chart.js`

**Effort**: Medium | **Value**: Medium

---

### 6. **Offline-First PWA** 
**Problem**: Technicians may work in areas with poor connectivity.
**Solution**:
- Add Service Worker + Workbox
- Cache boards, checklists, pending inspections locally (IndexedDB)
- Queue mutations offline → sync when online
- "Sincronizando..." indicator in header

**Effort**: High | **Value**: High (if field work is offline)

---

### 7. **Audit Trail / Event Log**
**Problem**: No immutable log of who did what when.
**Solution**:
- New table `audit_logs` (id, user_id, action, entity_type, entity_id, old_value, new_value, timestamp)
- Trigger on all mutations (boards, inspections, NCs, users)
- "Auditoria" view (supervisor only) with filters

**Effort**: Low-Medium | **Value**: Medium (compliance)

---

### 8. **Recurring Schedule Engine**
**Problem**: Frequency is just a label; no auto-scheduling.
**Solution**:
- When inspection completed → auto-calculate `next_due_date` based on frequency
- Supabase cron job creates "pending" inspection records for upcoming due dates
- Technician sees "Próximas preventivas" in dashboard
- Allow manual override (skip, reschedule)

**Effort**: Medium | **Value**: High

---

### 9. **Checklist Versioning & Templates**
**Problem**: Checklist definitions are static; changes affect history.
**Solution**:
- Version checklist definitions (add `version`, `effective_from`, `is_active`)
- When starting inspection → snapshot current checklist version
- Allow creating templates per board type
- Visual diff between versions

**Effort**: Medium | **Value**: Medium

---

### 10. **Mobile UX Polish**
**Problem**: Designed for desktop; mobile usage is painful.
**Solution**:
- Touch-friendly answer buttons (larger hit areas)
- Swipe gestures for checklist navigation
- Camera integration (capture photo directly)
- Bottom navigation bar on mobile
- Installable PWA manifest

**Effort**: Medium | **Value**: High

## Architecture Considerations

### Database
- Current RLS disabled → consider enabling with proper policies if multi-tenant
- Add indexes on frequently queried columns (`inspections.board_id`, `non_conformities.status`, `boards.frequency`)
- Consider partitioning `inspections` by date if volume grows

### Supabase Usage
- Move heavy logic to Edge Functions (notifications, reports, scheduling)
- Use Realtime for live dashboard updates (optional)
- Storage for photos (separate from DB)

### Frontend
- Consider React Query v5 optimizations (select, structural sharing)
- Code-split heavy views (history, issues) with `React.lazy`
- Error boundaries per view
